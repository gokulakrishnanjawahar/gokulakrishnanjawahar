## Flagship Projects
### Klyve — AI Motion Graphics SaaS

<div align="center">
<img src="https://readme-typing-svg.demolab.com?font=Fira+Code&size=16&pause=1500&color=7EE787&center=true&vCenter=true&width=600&lines=Text+%2B+Brand+Context+%E2%86%92+AI-Rendered+Launch+Videos;Template-Constrained+Generation%2C+Never+Free-Form+Code;Ranked+%2336+on+Product+Hunt+%C2%B7+23+Upvotes" alt="Klyve tagline" />
</div>

![Product Hunt](https://img.shields.io/badge/Product%20Hunt-Ranked%20%2336-DA552F?style=flat-square&logo=producthunt&logoColor=white)
![Status](https://img.shields.io/badge/Status-Live-brightgreen?style=flat-square)
![Solo Founder](https://img.shields.io/badge/Founder-Solo-blue?style=flat-square)

**What it is:** Klyve turns a company's text and brand context into fully rendered, on-brand launch videos — no editing software, no designer required. It's a solo-founder SaaS built from the ground up: idea, architecture, cloud infrastructure, outreach, and affiliate program.

**Core design principle — Template-Constrained Generation:**
Rather than letting an LLM write free-form animation code (fragile, unpredictable, hard to sandbox), Klyve constrains the model to emit **structured JSON props validated against a Zod schema**. Those props are injected into pre-built Remotion templates. This makes every output renderable, on-brand, and safe by construction.

**Pipeline:**

```
User Input (brand + text)
        │
        ▼
   Next.js Frontend
        │
        ▼
   Claude API  ──────►  Structured JSON (Zod-validated props)
        │
        ▼
  Remotion Lambda  ──────►  Parallel render workers (~40 concurrent)
        │
        ▼
   S3 / R2 Storage  ──────►  Finished MP4 delivered to user
```

**Infrastructure (AWS, eu-north-1):**

| Component | Detail |
|---|---|
| Render Worker (Lambda) | 3 GB memory, 2 GB disk, 15-min timeout, ~40 parallel workers per render |
| Screenshot Lambda | Headless Chromium — captures hero + scrolled sections of a product site for auto-generated brand assets |
| Media S3 Bucket | Private, signed-URL only — brand assets, narration audio, background music |
| Remotion S3 Bucket | Auto-managed by Remotion — compiled video bundles + finished renders |
| IAM Design | Two scoped users: one S3-only (media), one Lambda+Remotion-only (`remotion*` resources) |
| Lambda Concurrency | Raised to 1000 (default is 10) |

**Go-to-market:**
- Cold outreach campaign targeting recently funded AI startups
- Built a full spec video matching a prospect's exact design system as the primary portfolio asset
- Built an in-house affiliate dashboard for generating/managing referral codes — commission-only, zero upfront cost, no third-party affiliate infra

**Affiliate program design:**

| Constraint | Reasoning |
|---|---|
| Commission-only, no upfront pay | Keeps acquisition cost at zero until a sale actually closes |
| In-house dashboard, no third-party tool | Full control over code generation, tracking, and payout logic |
| No tech-stack / promotional language in affiliate materials | Affiliates sell the outcome, not the implementation |
| Sourced via curated outreach, not open community posts | Reddit-style open outreach produced low-quality, inexperienced leads |

### Influencity — Decentralized Influencer Protocol

<div align="center">
<img src="https://readme-typing-svg.demolab.com?font=Fira+Code&size=16&pause=1500&color=A78BFA&center=true&vCenter=true&width=600&lines=A+Decentralized+Influencer+Sponsorship+Protocol;Built+on+Polygon;Escrow+%2B+Milestone-Based+Payments" alt="Influencity tagline" />
</div>

![Chain](https://img.shields.io/badge/Chain-Polygon-8247E5?style=flat-square&logo=polygon&logoColor=white)
![Open Source](https://img.shields.io/badge/Open%20Source-Yes-success?style=flat-square)
![Category](https://img.shields.io/badge/Category-Web3%20%2F%20Creator%20Economy-purple?style=flat-square)

**What it is:** Influencer marketing runs on trust and manual invoicing — brands pay upfront and hope for delivery, or pay after and hope the influencer doesn't ghost. Influencity replaces that with an on-chain escrow protocol: funds are locked in a smart contract and released automatically as milestones are verified, removing the need for either party to trust the other.

**Why it matters:** This isn't a wrapper around a payment API — it's protocol-level design. Escrow logic, milestone verification, and payment release all live on-chain, on **Polygon** for low transaction costs at creator-economy scale.

**Core mechanics:**
- **Escrow-first** — sponsorship funds are locked in a smart contract before any content is delivered
- **Milestone-based release** — payments unlock incrementally as deliverables are met, not all-or-nothing
- **Trustless by design** — neither brand nor influencer needs to trust the other; the contract enforces the agreement
- **Polygon** — chosen specifically for low gas costs, making micro-sponsorship deals economically viable

## How I Work

I care more about **shipping something real** than polishing something theoretical. A few principles that show up across everything I build:

- **Constrain the model, don't trust it blindly.** Klyve's whole architecture exists because letting an LLM freehand output is fragile — schema-validated generation is safer and more debuggable.
- **Infra should be boring and cheap.** Klyve's AWS footprint is deliberately minimal — no CloudFront, no Bedrock, no ECS — just what's needed, scoped tightly with IAM.
- **Trust should be enforced by the system, not assumed.** Influencity's escrow-first, milestone-based design exists so neither party in a sponsorship deal has to rely on the other's word.
- **Ship in days, not months.** I'd rather get a real product in front of real users on Product Hunt than keep iterating in private.
- **Build in public.** Wins, numbers, and failures all go out on X — no highlight-reel-only approach.
